# NEXMIS 系統架構設計

> 版本：1.0（初版架構）　適用對象：MIS 維運人員、後續開發者

## 1. 設計目標與取捨

| 目標 | 設計決策 |
|---|---|
| 可正式部署、長期維護 | 單一語言（Go）撰寫中央服務與 Agent，共用協定套件；Web 端以 TypeScript 撰寫並內嵌進服務執行檔，部署只有「一個執行檔 + 一個 PostgreSQL」。 |
| 低資源消耗 | Agent 為原生 Go 執行檔（無 .NET / Python 執行環境依賴），閒置時記憶體約 15–25 MB、CPU 近 0%；盤點採差異上傳，心跳僅數十位元組。 |
| 高安全性 | 每台 Agent 以 Ed25519 金鑰對進行身分驗證；所有派送指令由伺服器簽章、Agent 驗章後才執行；Web 端採 RBAC 與完整稽核。 |
| 與 AD 隔離 | 中央服務**不安裝在網域控制站**，只以唯讀服務帳號透過 LDAPS 查詢；不寫入 AD、不修改 GPO、不需要 Domain Admin。 |
| 穩定、自動重連 | Agent 以 WebSocket 長連線，斷線採指數退避 + 隨機抖動重連；離線期間的結果暫存於本機佇列，重連後補送。 |
| 模組化擴充 | Agent 端以「能力（capability）」註冊指令處理器；伺服器以模組化 service 分層；協定以 `type` 欄位擴充，舊版 Agent 忽略不認得的訊息。 |
| 支援 Windows Home | 不依賴 RDP、WinRM、GPO 等 Pro 限定功能；遠端畫面、訊息、同意授權皆由 NEXMIS 自行實作。 |

## 2. 整體架構

```

  MIS 人員瀏覽器 │  HTTPS  ┌──────────────────────────────┐   LDAPS(636, 唯讀)   ┌─────────┐
  ─────────────────────▶ │  nexmis-server（中央服務）       │ ───────────────────▶ │ AD DC   │
                │         │  ├ Web 管理端（內嵌 SPA）         │                      └─────────┘
                │         │  ├ REST API / 即時事件 WS        │
                │         │  ├ Agent 閘道（WSS）              │   ┌──────────────┐
                │         │  ├ 排程器 / 部署引擎 / 探索掃描    │ ─▶│ PostgreSQL 16 │
                │         │  └ 遠端連線中繼（Relay）           │   └──────────────┘
                │         └──────────────▲───────────────┘
                └────────────────────────│────────────────────────────────────────┘
                                         │ WSS 443（Agent 主動連出，無需開放端點入站埠）
             ┌───────────────────────────┼───────────────────────────┐
     ┌───────┴────────┐          ┌───────┴────────┐          ┌───────┴────────┐
     │ Windows 電腦     │          │ Windows 筆電     │          │ 其他內網設備       │
     │ nexmis-agent    │          │ nexmis-agent    │          │ （印表機/交換器/NAS）│
     │  ├ 服務（SYSTEM） │          │  ├ 電池監控       │          │ 由探索掃描登錄      │
     │  └ 使用者端助手   │          │  └ ...           │          └────────────────┘
     └────────────────┘          └────────────────┘
```

### 2.1 元件

| 元件 | 技術 | 職責 |
|---|---|---|
| `nexmis-server` | Go 1.26、`net/http`、`coder/websocket`、`pgx` | REST API、Agent 閘道、事件推播、排程、部署、探索、AD 同步、遠端連線中繼、稽核。 |
| Web 管理端 | React 19 + TypeScript + Vite + Ant Design（繁中語系） | 編譯後以 `go:embed` 內嵌於 server 執行檔。 |
| `nexmis-agent` | Go 1.26、`golang.org/x/sys/windows`、WMI | 以 Windows 服務（LocalSystem）執行，負責盤點、健康、指令、部署、更新。 |
| 使用者端助手 | 同一個 `nexmis-agent.exe --user-helper` | 由服務在使用者登入的工作階段啟動，負責系統匣圖示、同意視窗、聊天視窗、畫面擷取與輸入注入。 |
| PostgreSQL 16 | | 唯一的狀態儲存；時序資料（健康、電池）以分區保存期限清理。 |

### 2.2 為何選 Go 而非 .NET / Node

- Agent 必須「零依賴」安裝於 Windows Home：Go 產出單一靜態執行檔，不需安裝執行環境。
- 中央服務可同時部署於 Linux（建議，Docker）或 Windows Server（服務模式），同一份程式碼。
- 伺服器與 Agent 共用 `internal/protocol`，協定變更由編譯器保證兩端一致。

## 3. 與 Active Directory 的整合與隔離

1. **部署位置**：nexmis-server 安裝於獨立的 Linux VM 或 Windows 成員伺服器，絕不安裝在 DC 上。
2. **權限**：使用一個一般網域使用者作為 LDAP 綁定帳號（只需「讀取」權限，預設網域使用者即可讀取電腦物件與群組）。
3. **協定**：LDAPS（636）或 LDAP + StartTLS；可設定驗證 DC 憑證。
4. **用途**：
   - 管理者登入：以 AD 帳號密碼進行 LDAP bind 驗證，依 AD 群組對應 NEXMIS 角色（例如 `NEXMIS-Admins` → 系統管理員）。
   - 電腦清單同步：定期（預設每 6 小時）讀取指定 OU 的電腦物件（名稱、OS、最後登入時間、OU 路徑、啟用狀態），與 Agent 回報資料比對，找出「AD 有但未安裝 Agent」的電腦。
5. **負載保護**：同步採分頁查詢（Paged Results 500 筆）、只取必要屬性、最短同步間隔 30 分鐘、單一連線；登入驗證有失敗次數鎖定，避免成為對 DC 的暴力破解跳板。
6. **不做的事**：不寫入 AD、不變更 GPO、不建立 SPN、不需要 Kerberos 委派。

## 4. Agent 與伺服器通訊

### 4.1 註冊（Enrollment）

```
Agent                                         Server
  │ 產生 Ed25519 金鑰對（私鑰以 DPAPI 機器範圍加密存放）
  │ POST /api/agent/v1/enroll                   │
  │ {enroll_token, machine_id, hostname,        │
  │  public_key, os, agent_version}  ─────────▶ │ 驗證註冊權杖（可設期限、次數上限）
  │                                             │ 建立/比對裝置（machine_id 去重）
  │ ◀───────── {agent_id, server_sign_key}       │
  │ 儲存 agent_id 與伺服器簽章公鑰（之後固定）
```

- `machine_id` 取自 `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`，重灌 Agent 仍能對應同一台裝置。
- 註冊權杖可由 MIS 在 Web 端建立，搭配安裝參數大量部署（GPO 啟動指令碼、Intune、手動）。

### 4.2 連線驗證

1. Agent 連線 `wss://server/api/agent/v1/ws`。
2. 伺服器送出 `auth.challenge {nonce}`。
3. Agent 回 `auth.response {agent_id, ts, signature = Ed25519(nonce ‖ agent_id ‖ ts)}`。
4. 伺服器以註冊時記錄的公鑰驗章，時間差須在 ±5 分鐘內；通過後送 `auth.ok`。

TLS 由伺服器（或前端反向代理）提供；Agent 預設驗證伺服器憑證，可在安裝時指定企業內部 CA 憑證或憑證指紋釘選。

### 4.3 指令簽章（深度防禦）

伺服器持有一把獨立的 Ed25519 簽章私鑰。所有會改變端點狀態的訊息（指令、部署、重新開機、遠端連線請求）都包含：

```
signed = Ed25519(server_key, canonical_json(command) ‖ agent_id ‖ issued_at ‖ expires_at)
```

Agent 只執行：簽章正確、目標是自己、未過期、`command_id` 未曾執行過（防重送）的指令。即使 TLS 被中間人攔截，也無法偽造指令。

### 4.4 訊息格式

所有 WebSocket 訊息使用 JSON 信封：

```json
{ "t": "heartbeat", "id": "01J...", "ref": "", "p": { ... } }
```

- `t`：訊息類型；`id`：訊息 ID（ULID）；`ref`：回覆的訊息 ID；`p`：內容。
- 不認得的 `t` 一律忽略，確保新舊版本相容。
- 詳見 `internal/protocol`。

### 4.5 回報頻率（可於伺服器設定）

| 資料 | 頻率 | 說明 |
|---|---|---|
| 心跳 | 60 秒 | 含 CPU/記憶體/開機時間/登入使用者，用於線上狀態 |
| 健康診斷 | 15 分鐘 | 磁碟、SMART、Defender、更新、事件記錄錯誤、待重開機 |
| 電池 | 6 小時 | 設計容量、充飽容量、循環次數、健康百分比 |
| 硬體盤點 | 24 小時 + 開機 | 差異比對，無變化只送雜湊 |
| 軟體盤點 | 6 小時 | 同上 |

### 4.6 自動重連

- 指數退避：1s → 2s → 4s … 上限 5 分鐘，加上 ±20% 隨機抖動，避免伺服器重啟時所有 Agent 同時湧入。
- 應用層 ping 每 30 秒；連續 3 次無回應即判定斷線重連。
- 指令結果先寫入本機佇列（上限 500 筆），伺服器儲存後回覆 `command.result.ack` 才刪除；斷線或重開機後重連會補送尚未確認的結果，伺服器對重複結果只回覆確認、不重複套用。已開始執行的指令不受斷線影響，會繼續執行到完成。

## 5. 使用者工作階段與同意授權

Windows 服務執行於 Session 0，無法顯示視窗或擷取使用者畫面。因此：

1. 服務偵測使用者登入（`WTSGetActiveConsoleSessionId` + 工作階段變更通知）。
2. 以 `WTSQueryUserToken` + `CreateProcessAsUser` 在該工作階段啟動 `nexmis-agent.exe --user-helper`。
3. 服務與助手之間以具名管道 `\\.\pipe\nexmis-helper-<session>` 溝通，管道 ACL 僅允許 SYSTEM 與該工作階段使用者。
4. 助手負責：
   - **連線同意**：MIS 請求遠端連線時跳出視窗，顯示請求者姓名、目的、模式（僅檢視／可操作），使用者按「允許」或「拒絕」，逾時（預設 60 秒）視為拒絕。
   - **雙向訊息**：聊天視窗，使用者也可從系統匣主動向 MIS 發起求助。
   - **安全重新開機**：顯示倒數通知，允許使用者延後（次數與時間由政策控制）、儲存工作。
   - **畫面擷取與輸入**：僅在同意後啟動，連線期間螢幕角落持續顯示「MIS 正在檢視/操作您的畫面」並提供「立即中斷」按鈕。

同意政策可依裝置群組設定：`always_ask`（預設）、`notify_only`（只通知，適用無人值守的公用電腦）、`deny`。

## 6. 遠端桌面與畫面分享

- **不使用 RDP**（Windows Home 不支援 RDP 主機），由 NEXMIS 自行實作。
- 第一版：助手以 GDI/DXGI 擷取畫面，切成區塊並只傳送變動區塊（JPEG 壓縮、品質自適應），經伺服器中繼 WebSocket 傳到瀏覽器 Canvas；瀏覽器的滑鼠/鍵盤事件經伺服器回傳，由助手以 `SendInput` 注入。
- 中繼模式的優點：Agent 只需連出 443，穿越防火牆最簡單；伺服器可完整稽核連線起訖。
- 後續版本：升級為 WebRTC（pion），伺服器僅作信令，畫面點對點傳輸以降低伺服器頻寬。
- 限制：UAC 安全桌面與登入畫面在第一版無法擷取（需 SYSTEM 端擷取，列入後續規劃）。

## 7. 指令執行、重開機與軟體部署

| 功能 | 說明 |
|---|---|
| 遠端指令 | PowerShell / CMD，指定逾時（預設 5 分鐘、上限 1 小時），輸出上限 1 MB，於 SYSTEM 執行。可建立「指令庫」供重複使用。 |
| 安全重新開機 | 先通知使用者並倒數（預設 5 分鐘），使用者可延後；無人登入時立即執行；可選擇強制。 |
| 軟體部署 | 上傳 MSI/EXE/MSIX 套件與靜默參數 → 建立部署工作指定目標（裝置/群組/標籤）→ Agent 以一次性下載權杖取得檔案、驗證 SHA-256 後安裝 → 回報結束碼。支援排程時段與失敗重試。 |
| 排程 | Cron 語法，可排程指令、部署、盤點、重新開機。 |

所有指令僅具「operator」以上角色可派送，且全部寫入稽核紀錄（誰、何時、對哪台、內容、結果）。

## 8. 設備探索

1. **Agent 回報**：已安裝 Agent 的電腦。
2. **AD 同步**：AD 電腦物件，標示是否已安裝 Agent。
3. **網段掃描**：由伺服器（或指定的 Agent 作為探索代理，用於伺服器無法直達的網段）對 CIDR 進行 ICMP / TCP 常用埠（22、80、135、139、443、445、515、631、3389、8080、9100）探測，並查詢反向 DNS、NetBIOS 名稱、MAC（ARP 表）與廠商（OUI），推測設備類型（印表機、網通、伺服器、Windows 電腦）。掃描有速率限制，避免影響網路。

## 9. 設備生命週期

狀態：`採購中 → 庫存 → 使用中 → 維修中 → 閒置 → 報廢`，每次變更記錄時間、操作者與原因；裝置欄位含資產編號、保管人、部門、地點、購買日期、保固到期日。保固即將到期與電池健康低於門檻會出現在儀表板。

## 10. 安全設計摘要

- Web：HttpOnly + Secure + SameSite=Strict 工作階段 Cookie；伺服器端工作階段可撤銷；Origin 檢查防 CSRF；登入失敗鎖定。
- 密碼：本機帳號以 Argon2id 雜湊；AD 帳號不存密碼。
- RBAC：`admin`（全部）、`operator`（指令、遠端、部署）、`helpdesk`（遠端協助與訊息）、`viewer`（唯讀）。
- 稽核：所有寫入操作、登入、遠端連線起訖、指令內容與結果，寫入只能新增的稽核表（資料庫層以觸發程序禁止 UPDATE/DELETE）。
- 祕密：AD 綁定密碼以伺服器主金鑰（AES-256-GCM）加密後存入資料庫；主金鑰來自環境變數或金鑰檔。
- Agent：安裝目錄與資料目錄 ACL 僅允許 SYSTEM 與 Administrators；私鑰以 DPAPI 保護。

## 11. AI 智慧診斷擴充點（預留）

- 所有健康資料、事件記錄摘要、指令結果皆結構化保存，可直接作為 AI 診斷輸入。
- 伺服器預留 `diagnostics` 模組介面：輸入裝置 ID → 彙整近期健康、事件、盤點變化 → 交由 LLM 產出診斷建議與建議指令；建議指令需人工確認後才派送（Human-in-the-loop）。
- 自動維運規則（例如「磁碟剩餘 < 10% 自動清除暫存」）以「規則 → 動作」形式建立在排程與指令庫之上。
